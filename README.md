## 1. 这个项目解决什么问题

大学数学自学时，大多数人卡在**四个具体的地方**：

| 卡点 | 具体表现 | 本项目怎么解决 |
| --- | --- | --- |
| **定义看不懂** | 教材上"设函数 f 在 U(x₀, δ) 内有定义……"，每个字都认识，连起来不知道在说什么 | 每条定义都配一个 **「说人话」** 板块，用生活场景重讲一遍；再配「为什么要这样想」，解释这个绕口的定义是被什么问题逼出来的 |
| **定理只会背不会用** | 会复述"罗尔定理：连续、可导、两端相等 ⇒ 存在 ξ 使 f′(ξ)=0"，看到题却不知道从哪下手 | 每条定理给 **完整分步证明** + **「为什么要这样想」**（辅助函数是怎么想到的）+ **「容易错的地方」** |
| **刷题没梯度** | 一上来就刷难题，或者刷来刷去都是同一种难度，不知道自己到底哪一档不会 | **四档难度阶梯**出题：入门 → 基础 → 提高 → 挑战，做完一档才解锁下一档；答完给出每一档的正确率 |
| **错题本记了就再也不看** | 抄了一大本错题，抄完就吃灰 | 错题**自动**进本，按**先快后慢的记忆规律**排期，到期自动弹窗提醒复习；定义和定理也能加进来一起复习 |

面向的用户：**大学一年级、数学学得有点吃力、希望有人用大白话再讲一遍的人**。
所有讲解都刻意写到**初中生也能听懂**，同时**并行保留严谨的数学表述** —— 两条线并排放，你爱看哪条看哪条。

## 2. 主要功能

### 版块一：组题组 —— 同一知识点，难度层层递进

不是"随机抽 10 题"，而是给你一条**学习路径**。

| 档位 | 难度 | 长什么样 |
| --- | --- | --- |
| 第 1 档 | 入门 | 直接套定义或公式，先热身 |
| 第 2 档 | 基础 | 需要一两步变形 |
| 第 3 档 | 提高 | 要选对方法，多步推理 |
| 第 4 档 | 挑战 | 综合多个知识点或带陷阱 |

- **出题范围**三种模式：
  - **按章节 / 小节**（默认）—— 树形选择器：先勾章，点开后可细选到具体小节；
    章的复选框支持"部分选中"中间态；带关键字搜索（章名、小节名都能搜）；每章每节显示题量
  - **按知识点** —— 选 1~3 条定义/定理，围绕它们组一条难度阶梯
  - **全书混合** —— 从所有章节挑题，难度仍按梯队往上走
- **题量**：小份 6 题 / 中份 8 题 / 大份 12 题（实际题量受该知识点题量限制）
- **题型筛选**：选择题 / 填空题 / 判断题 / 计算题 / 证明题
- **难度范围**：四档自由勾选
- **答题反馈**：选择题点选即判；填空/计算/证明先写再看答案；每题给出「正确答案 + 解析」
- **可复现**：同一个 seed 生成同一套题（`buildQuiz({ seed })`），方便分享与复现
- **做完给报告**：各难度档正确率、"需要回头看的知识点"、薄弱点一键再练
- 做错的题**自动进错题本**

> 题库现状：**194 道原创题**，覆盖 7 章。每个知识点卡片上直接标着它的配套题量，
> 配套题最多的知识点有 9 道（如"第一类换元积分法"、"微分的定义"）。

### 版块二：错题本 —— 按记忆规律提醒你复习

复习间隔（想换成自己的节奏，改 `js/srs.js` 里的数组即可）：

```
5 分钟 → 30 分钟 → 12 小时 → 1 天 → 2 天 → 4 天 → 7 天 → 15 天 → 30 天 → 60 天
```

共 **10 档，走完算"已掌握"**。

- **答对** → 进入下一档，间隔变长
- **答错** → 打回上一档，很快再来一次，并记一次"卡壳"
- **自动提醒**：打开网页时若有到期内容 → 弹窗 + 提示音（20 分钟内不重复弹，可关）
- **遮盖式复习**：先自己回忆 → 点「显示答案」→ 自评「记住了 / 忘了」；支持键盘操作
- **遗忘曲线示意图**：内置一张 SVG，直观解释"为什么间隔一次比一次长"
- **四个标签页**：待复习 / 错题 / 收藏 / 已掌握
- **按章节分组**、导出 JSON、打印 / 存 PDF
- **定义和定理也能加进错题本**，和题目一起排进复习队列

> 说明：这组间隔是"遗忘曲线思路 + 常见实践"的组合，**不是**艾宾浩斯 1885 年论文里的原始数值。

### 版块三：教材定理定义详细解 —— 通俗解释 + 完整证明

左边目录按 **章 → 节 → 定义/定理** 层层点开，右边是条目卡。每个条目 6 个板块：

| 板块 | 作用 |
| --- | --- |
| **严谨说法** | 教材级别的正式表述，公式用 ε-δ 等规范写法 |
| **说人话** | 用初中生能听懂的话 + 生活比喻再讲一遍 |
| **为什么要这样想** | 这个定义/证明是怎么想出来的（自学者最缺的部分） |
| **证明 / 推导** | 定理给完整分步证明；公式给推导过程 |
| **举个最小例子** | 一个能立刻算出来的例子 |
| **容易错的地方** | 学生真实会踩的坑 |

- 定义用蓝色标签 `定义`，定理用紫色标签 `定理`，**一眼区分**
- **全文搜索**：名称、别名、严谨说法、通俗解释、证明、标签都能搜
- **筛选**：只看定义 / 只看定理 / 只看已收藏 / 只看在错题本的
- **相关条目互相跳转**（罗尔 ↔ 拉格朗日 ↔ 柯西 ↔ 泰勒）

## 3. 安装方法

### 环境要求

**只需要 Node.js 18 或更高版本。** 没有别的依赖，不用 `npm install`。

```bash
node -v      # 应该 >= v18
```

### 获取代码

```bash
git clone https://github.com/<你的用户名>/<仓库名>.git
cd <仓库名>
```

### 启动

```bash
npm start
# 或者指定端口
node scripts/serve.mjs 8080
```

看到这段输出就成功了：

```
  数学陪练已启动：http://localhost:5173

  三个版块： #/practice  组题组
            #/notebook  错题本
```

浏览器打开 **http://localhost:5173** 即可。

### 部署到网上

**已开启 GitHub Pages，可以直接在线访问：**

### 👉 https://vanilla-icewagtail.github.io/math-improvement-plan/

推送到 `main` 且 CI 通过后会自动发布，不需要手工操作。

仓库自带 GitHub Actions 工作流 [`.github/workflows/ci.yml`](.github/workflows/ci.yml)，

| CI 步骤 | 做什么 |

### 数学记号怎么写的（给贡献者）

极限号在渲染时会自动排成**教科书样式**——`lim` 与趋近条件上下居中，而不是写成 `lim(x→0)`。
`js/math.js` 会识别下面几种写法，你按习惯写任意一种都行：

| 你写的 | 渲染成 |
| --- | --- |
| `lim(x→0)` | lim，下方居中 `x→0` |
| `lim[x→0]` | 同上 |
| `lim_{n→∞}` | 同上（LaTeX 风格） |
| `lim<sub>x→a</sub>` | 同上 |
| `lim(x→0<sup>+</sup>)` | 支持单侧极限记号 |
| `lim f(x)` | **前置式保持并列**（教科书里这类极限就是 lim 与表达式并排，塞进下标反而是错的） |

> 实现上有个坑值得注意：渲染必须分两步——先把记号换成占位符，**再**做 HTML 转义，
> 最后才把占位符展开成真标签。如果反过来在转义前插入标签，属性里的引号会被转义成
> `&quot;`，标签就再也还原不回来了。见 `js/math.js` 顶部的说明。

### 答题时输入数学符号

中文输入法下打 `<`、`ε` 这类符号往往要切回英文，很麻烦。所以答题框上方有一排
**常用符号按钮**（`<` `>` `≤` `≥` `≠` `→` `∞` `ε` `δ` `Δ` `π` `∫` `√` `∈` `±` `′`），
点一下插入到光标处，不依赖输入法。

答案里的尖括号会被安全转义（`x < 1` 显示为 `x < 1`），不会破坏页面。

### 命令行工具的代理问题（中国大陆常见）

`git` 和 `gh`（GitHub CLI）**都不读 Windows 系统代理**，只认 `HTTP_PROXY` / `HTTPS_PROXY`
环境变量。如果你的网络需要代理才能访问 GitHub，有两种做法：

**做法一：只给 git 配（推荐，作用面最小）**

```bash
git config --global http.https://github.com.proxy "http://127.0.0.1:7890"
```

只对 github.com 生效，不影响 gitee / 公司 GitLab 等其它站点。

**做法二：给 gh 用包装脚本（不污染系统环境变量）**

```bash
npm run ghp -- auth status
npm run ghp -- pr list --limit 5
npm run ghp -- -NoProxy api user     # 临时直连
npm run ghp -- -Check                # 只探测代理端口是否在监听
```

或直接调用 `tools\ghp.cmd <gh 参数>`。相关文件：

| 文件 | 说明 |
| --- | --- |
| [`tools/ghp.ps1`](tools/ghp.ps1) | 只在单次调用内注入代理，**不改动用户/系统环境变量** |
| [`tools/ghp.cmd`](tools/ghp.cmd) | cmd.exe / Git Bash 下的包装，顺带绕过 PowerShell 执行策略 |

> **为什么不直接把代理写进用户环境变量？**
> 那样一旦代理软件（Clash 等）没开，`gh` 会立刻失败，而且 `npm` / `pip` / `curl`
> 等一切认这些变量的工具都会连锁失败。包装脚本的方式下，代理挂了只影响这一个脚本。
>
> 代理地址默认 `http://127.0.0.1:7890`，可用环境变量 `GHPROXY` 覆盖；
> 设 `GHPDIRECT=1` 可强制直连。

## 4. 使用方法

### 4.1 组题组：练一个知识点

1. 打开 `#/practice`（默认页）
2. **① 想练什么** → 选「按知识点（推荐）」
3. **② 点选知识点** → 搜索框输入 `罗尔`，点中「定理 罗尔定理 3」
   （按钮末尾的数字是**该知识点的配套题量**）
4. **③ 题量** → 中份（8 题）
5. **④ 难度范围** → 一个都不选 = 四档全要
6. **⑤ 题型** → 一个都不选 = 全部题型
7. 点 **「生成我的题组」**
8. 逐题作答：选择题点选项即判分；填空/计算/证明先自己在纸上算，再点「提交答案」或「不会，直接看答案」
9. 每答完一档会提示进入下一档；全部做完点「查看本组结果」
10. 报告里点「再练这个知识点」，可以围绕薄弱点立刻再来一组

> 也可以点 **「随便来一个知识点」**，让系统挑一个配套题量充足的知识点。

### 4.2 错题本：复习到期内容

1. 打开 `#/notebook`
2. 顶部四个数字：现在就该复习 / 今天以内 / 总条数 / 已掌握
3. 有到期内容时点 **「开始复习」** → 逐条遮盖式自评：
   - 先自己回忆 → 按 `空格` 或点「显示答案」
   - 想起来了按 `2`（或点「记住了」）→ 进入下一档
   - 想不起来按 `1`（或点「忘了」）→ 打回上一档
4. 在「错题」标签页里可以**按章节分组**查看全部错题，每条支持：
   - 「同类再来几题」→ 围绕这条的知识点立刻生成一个小题组
   - 「展开看内容」→ 弹出完整题目 / 定理卡
   - 「导出错题本」/「打印 / 存 PDF」

### 4.3 教材区：查定义、看证明

1. 打开 `#/textbook`
2. 左边目录点开「第 3 章 微分中值定理与导数的应用」→ 点「3.1 微分中值定理」
   （整章也能一键「展开本章」）
3. 找到 **罗尔定理** 卡片，从上往下读：严谨说法 → 说人话 → 为什么要这样想 → 证明 → 例子 → 易错点
4. 快速找内容：用顶部搜索框（或按 `/`），输入 `罗尔` / `夹逼` / `曲率` 都能搜到
5. 想只看定理：点「只看 → 定理」
6. 卡片右上角：
   - 点 ⭐ → 收藏（之后在「错题本 → 收藏」集中看）
   - 点 📕 → 加进错题本，会按记忆间隔提醒你回看这条定理

### 4.4 收藏与错题本的图标

### 5.2 网站里的输入 → 输出：答一道题

**输入**（题目 `q-ch3-001`，难度 1，选择题）：

```
题干：下列函数中，在给定区间上满足罗尔定理全部条件的是（　　）。
  A. f(x) = |x|     在 [-1, 1] 上
  B. f(x) = 1/x     在 [-1, 1] 上
  C. f(x) = sin x   在 [0, π] 上
  D. f(x) = x       在 [0, 1] 上

用户点击：C
```

**输出**：

```
✅ 答对了！

正确答案：C

解析：
思路：罗尔定理要求三条：闭区间连续、开区间可导、两端点函数值相等。
步骤：sin x 在 [0, π] 连续、在 (0, π) 可导（导数为 cos x），且 sin 0 = sin π = 0，
      三条全部满足；|x| 在 x = 0 不可导；1/x 在 x = 0 无定义，不连续；
      f(x) = x 的两端点值为 0 与 1，不相等。
结论：选 C。
提醒：验证定理条件时三条要逐条检查，缺一条定理就不能用；本题 C 的结论点是 x = π/2。
```

**答错时**的输出：除了上面的「正确答案 + 解析」，还会多显示一块「你写的」，
并提示「答错了，已自动记入错题本」—— 这条题立刻进入复习队列（第 1 档 = 5 分钟后）。

### 5.3 复习的输入 → 输出：一次自评

**输入**（错题本「待复习」里的一条，当前处于第 3 档）：

```
当前状态：phase = 3，due = 现在（已到期）
用户点：「记住了」
```

**输出**：

```
阶段 3 → 4
下次复习时间 = 现在 + INTERVALS[4].ms = 现在 + 2 天
提示条：「记住了！阶段 3 → 4，下次 2 天后」
错题本列表里该条的到期标签变成「还要 2 天」
```

若点「忘了」：`phase 3 → 2`，下次 = 现在 + `INTERVALS[2].ms` = 12 小时后，卡壳次数 +1。

**完整的自评规则表**（实测输出，见 `js/srs.js` 的 `grade()`）：

| 当前档位 | 点「记住了」 | 点「忘了」 |
| --- | --- | --- |
| 第 1 档（`phase 0`，刚加入错题本） | → 第 2 档（30 分钟后） | → 仍是第 1 档（**5 分钟后**马上再来） |
| 第 2 档 | → 第 3 档（12 小时后） | → 第 1 档（5 分钟后） |
| 第 3 档 | → 第 4 档（1 天后） | → 第 2 档（30 分钟后） |
| 第 4 档 | → 第 5 档（2 天后） | → 第 3 档（12 小时后） |
| 第 10 档（`phase 9`） | → 第 11 档 = **已掌握**（60 天后） | → 第 9 档（30 天后） |
| 已掌握（`phase 10`） | 保持已掌握（60 天后循环） | → 第 10 档（60 天后） |

规则总结：**答对升一档，答错降一档；还没真正记住过（第 1 档答错）就退回"5 分钟后再来"**。

## 7. 已知限制

诚实列出来，免得你踩坑：

1. **填空题判分是字符串比对**（已做全角/半角、括号、空白的归一化），
   **不做法等价性判断**。写成 `1/3` 和 `0.333` 这类差异会被判错。
   影响：可能被误判进错题本，手动移出即可，不影响学习。
2. **知识点配套题量不均**：194 道题摊到 200+ 个知识点上，部分知识点只有 0~2 道题。
   `npm run validate` 的备注区会列出所有配套题少于 3 道的知识点。
3. **题组可能出现档位跳空**：某知识点只有难度 1 和难度 3 的题时，就没有第 2 档。
   第 5.1 节给了一个真实例子。
4. **复习间隔是固定表**，不根据个人答题速度或正确率自适应。
5. **设置里的"每日目标"目前只保存、未参与统计**（预留给后续版本）。
   `npm run verify-readme` 会守住这条限制说明的真实性。
6. **视觉未经自动化验证**：无头浏览器在开发环境中不可用，
   功能由 44 项端到端断言覆盖，但配色与排版请自行过目。
